# 設計判断

- Node.jsの標準機能のみで静的HTMLを生成する。更新頻度・規模に対してサーバーやCMSの運用は不要。HTMLはJSが無効でも読める。
- 原稿と作品情報をページ実装から分離する。作品数・ジャンル・章数はデータから生成する。
- `/bookshelf/` を既定の配置先にする。ルート・別階層でも同じ生成器を使える。
- yu-zora.comの紺色と淡い橙を引き継ぎ、読書部分は生成りの紙と明朝体にする。外部フォントを使わず端末の日本語フォントを使う。
- 原稿は完成済み『雨を閉じこめる』の30章をコピーした。制作資料は公開対象に含めない。人物画はユーザーが採用した中間段階の線画を採用し、誇張した別案は使わない。
- 各章は固定HTML。検索・読書設定・しおりのみクライアント側JavaScript。読書位置は作品IDごとに保存し、破損値や範囲外の章番号を無視する。
- 人物画・配置図は読書を遮らない開閉式。北町資料室の図は該当章にのみ掲載する。
- Pages公開は手動実行。ポータル本体のデプロイ方式を決めつけない。公開先設定をビルド時に注入し、成果物を移植できるようにする。
- 試験では文字数だけでなく、生成した全HTMLのリンク・画像・フラグメントも解決する。公開前の視覚確認は別途行う。

## 旧版のアクセス制御（2026-09-20）

旧版の閲覧制限はCloudflare Workerで、ASSETS呼出しより前に行う。最新版の経路と共用図版は認証不要とし、ビルド時に生成する版ポリシーから判定する。URLのデコードと曖昧な経路の拒否を先に行い、画面、直接URL、全文テキスト、旧版専用画像に同じ判定を適用する。

セッションにはサーバー側Secretで署名した8時間のCookieを使用する。POSTは同一オリジンに限定し、認証画面はsame-originのReferrer-Policyを使ってフォームのOriginを維持する。認証済み応答を共有キャッシュへ保存しない。Secret不足時は旧版だけを閉じる。純静的ホスティングでは認証を担保できないためPagesへの公開ワークフローを廃止した。Git管理の原稿や履歴を暗号化する仕組みではなく、本棚サイトの閲覧制御である。

Wranglerは4.135.0を開発依存として固定。従来の4.120.0では本番のcompatibility_dateに対応するローカルランタイムが起動しなかったため更新した。依存監査で検出事項は0件。
